# 核心概念

> 六个词，看懂这一页，后面所有页面都能看懂。
> 这一页是全站最重要的内容，建议读两遍。

## 一、一张图看懂

```
组织（集团）
  └── 组织（分公司）
        └── 场站（1号厂房）        ← 数据根：所有分析从这里开始
              ├── 用能区域（生产区）  ┐
              ├── 用能分项（动力）    ├─ 三条独立的分类线
              ├── 空间位置（北侧）    ┘
              │
              └── 设备（进线总表）    ← 真正采集数据的对象
                    ├── 设备（车间总表）
                    └── 设备（支路表）
```

## 二、六个概念逐个说

### 1. 组织

**企业层级**，比如「集团 → 华东分公司 → 苏州工厂」。

- 组织只回答「归谁管」，不承载用能数据
- 可以多层嵌套
- 一个组织下可以有多个场站

> 只有一个厂区时，可以不建组织，直接建场站。

### 2. 场站

**物理地点**，比如「1号厂房」「苏州工业园区」。

**这是整套系统最重要的概念**，因为：

- 所有分析都以场站为边界
- 客户用户只能看到自己名下的场站
- 设备必须挂到场站，否则在任何报表里都不出现

| 建场站的原则 | 反例 |
| --- | --- |
| 按物理边界：楼栋、车间、配电室 | ❌ 按设备类型：「所有电表」 |
| 一个场站 = 一个可独立核算的用能单元 | ❌ 一个场站塞进整个集团 |
| 名称带地点：「1号厂房」「东区泵站」 | ❌ 名称带编号：「场站001」 |

#### 现在看哪个场站：右上角那一个选择器

> **这个选择器只有客户能看到**。租户管理员登录后右上角没有它 —— 场站是客户的账，
> 租户看到的是跨客户的运营面（厂商与型号、能源字典、品种指标），
> 那些数据不按场站切。租户要看某个客户的场站数据，走「客户与用户 → 客户行图标」下钻。


登录后，**每一页的右上角**都有一个「场站」下拉（树形：组织 → 子组织 → 场站）。
它决定你在这个页面看的是哪一个场站的数据：

| 页面 | 切场站后跟着变的东西 |
| --- | --- |
| 能耗概览 / 历史能耗 / 分项 / 区域 / 参数报表 / … | 整块看板的所有部件（同一个场站口径） |
| 设备管理 | 设备列表与顶部台数 |
| 设备分组 | 左侧结构树（只留这个场站的分项 / 区域 / 性质 / 位置） |
| 设备拓扑 | 拓扑卡片列表 |
| 告警中心 | 告警条数与分页 |

几个约定：

- **没有「全部场站」**。场站是计量与核算的最小单位，电价、变压器容量、
  计量口径各站不同，跨站加总是没有业务意义的数字。
- 默认选记忆里的场站；第一次进来选第一个。选择记在浏览器里（换浏览器要重选）。
- **「组织与场站」页不显示这个选择器** —— 那一页的职责就是管理整棵树，
  在它上面挂一个「当前场站」只会让人误以为列表被过滤了。
- 场站选择只改**看哪里**，不改**能看到什么**：权限仍由账号的场站授权决定，
  切换选择器不会让你看到未授权的场站。

### 3. 区域 / 分项 / 空间位置（三条分类线）

这三个都是**场站内部的分类方式**，互相独立：

| 维度 | 回答什么问题 | 例子 |
| --- | --- | --- |
| **用能区域** | 哪个功能分区用的？ | 生产区、办公区、仓储区 |
| **用能分项** | 什么用途用的？ | 动力、照明、空调、特殊设备 |
| **空间位置** | 在哪一层哪一侧？ | 3 楼东侧、厂区北侧 |

**关键理解**：一台设备可以**同时**属于三条线。比如「空压站表」可以同时是：

- 用能区域 = 生产区
- 用能分项 = 动力
- 空间位置 = 厂区南侧

**为什么分三条线**：因为它们回答的是不同问题。老板问「办公区这个月花了多少」是区域；设备主管问「空调用电涨了吗」是分项。两个问题都要能答。

> **注意**：界面上「按区域」和「按分项」是**二选一**的切换，不能同时叠加。
> 因为两条线交叉会出现重复计算 —— 一台设备既在生产区又是动力分项，
> 两边加起来会算两遍。

### 4. 设备

**真正采集数据的对象**。一台物理表计 = 一台设备。
| 属性 | 作用 | 取值 |
| --- | --- | --- |
| **用能品种** | 它用的是什么能源 | 电能 / 水 / 燃气 / 蒸汽 / 热力 |
| **设备一级类型** | 它是什么**物理设备** | 电能表 / 水表 / 燃气表 / 蒸汽表 / 热力表 / 环境设备 / 逆变器 / 智能空开 / 发电机组 |
| ↑ 说明 | **选了一级类型，品种自动带出** | 选「电能表」= 用能品种是电，不用再选一次 |
| **设备二级类型** | 它在系统里**干什么用** | 普通表 / 用户关口表 / 并网表 / 汇流表（水/气/汽/热只保留「普通表」一项） |
| **厂商型号** | 硬件规格与报文映射 | DTS634、DDSU666…（型号上带**接线方式**） |
| **层级** | 决定总分关系 | 1 = 总表（进线）<br>2 = 分表（车间、楼层）<br>3 = 支路表（末端回路） |

#### 六个核心字典，各管一件事

这是整个平台的底座。**它们互相独立，不能用一个下拉表达两个维度**：

| 字典 | 回答什么问题 | 在哪维护 |
| --- | --- | --- |
| **用能品种** | 烧的什么能源 | 运营配置 → 品种指标 |
| **一级设备类型** | 什么物理设备（带角色） | 运营配置 → **设备类型** |
| **二级设备类型** | 干什么用（不带角色） | 运营配置 → **设备类型** |
| **接线方式** | 几个相别（单相 / 三相四线 / 三相三线） | 型号上设置 |
| **厂商型号** | 硬件规格 + 厂家 key 怎么对 | 运营配置 → 厂商与型号 |
| **标准 key** | 平台认什么数据 | 品种指标（定义）+ 设备类型（绑定） |

#### 为什么要分成「物理设备」和「业务用途」两层

现场真实情况是这样的：

```
DTS634 这个型号（三相四线电能表）
  ├── 装在配电室进线柜 → 台账记作「用户关口表」
  ├── 装在车间配电箱   → 台账记作「普通表」
  └── 装在光伏并网点   → 台账记作「并网表」
```

**同一个型号，三种用途**。所以：

- **一级（物理设备）** = 这台硬件是什么 → 决定于型号，选型号时就知道是电能表；
- **二级（业务用途）** = 这台装在哪儿、算什么账 → 决定于安装位置，只有建档的人知道；
- **接线方式** = 有几个相别 → 型号出厂就定了，同一型号做不出两种相别。

三者互相独立，建档时各选一次，谁也不约束谁。

> ⚠️ **不能把「用途」和「相别」放进同一个下拉**。
> 改造前「单相电能表 / 电能表」两个档案就是按月相别拆分的，
> 结果实测有 **17 台设备**的型号与档案相别矛盾 ——
> 「单相电能表」档案下挂着 15 台三相型号。报表照常出，只是显示互相打架。

#### 角色挂在一级类型上，不挂二级

| 角色 | 含义 | 进抄表清单 | 例子 |
| --- | --- | --- | --- |
| **计量器具** | 有表底读数，能抄、能算账 | ✅ | 电能表、水表、燃气表 |
| **传感器** | 只上报数值，没有表底 | ❌ | 环境设备、逆变器、发电机组 |
| **受控设备** | 主要下发控制指令 | ❌ | 智能空开 |
| 其他 | 系统级参数 | ❌ | — |

**为什么不能按品种猜**：电能下既有电能表（要抄），也有智能空开、逆变器（不抄）。
光看「它属于电能」判断不了能不能抄 —— 必须看角色。

#### 标准 key 绑在「一级设备类型 × 接线方式」上

不是绑在二级类型上。判据很直接：改造前电能下 4 个二级类型
（普通表 / 并网表 / 用户关口表 / 汇流电表）**全部「继承品种全集」** ——
说明二级类型从来不决定采什么。

真正决定的是**相别**：

```
电能表 × 单相表（1P2W）    → 32 个 key，没有 B 相 / C 相
电能表 × 三相四线（3P4W）  → 48 个 key，全相
电能表 × 三相三线（3P3W）  → 目前 0 个（见下）
```

**普通表和关口表采的物理量完全一样**，只是台账归类不同。

> ⚠️ **三相三线暂时没有可用的 key**。它测的是线电压（Uab / Ubc / Uca），
> 而现有指标全是相电压 / 相电流，语义不同，配了也采不到数。
> 要支持它得先到「品种指标」补一组线电压指标。

#### 不能细分的设备，二级只有「普通表」一项

水表、燃气表、蒸汽表、热力表这几类现场基本只有一种设备，二级只保留「普通表」一项，
建档时选了一级就自动带出，不用再选。

这与电能表的「普通表」是**同一套口径**。以后现场真出现了总表/分表之分，
直接到「设备类型」页给该品种加一个「用户关口表」即可，不用改代码。

#### 场站声明了哪些品种，这个场站的设备就只出现哪些

场站建档时会勾选「用能品种」（例如某个园区只有电和水）。
之后在这个场站下建设备，**一级类型下拉只显示电能表和水表**，
不会出现燃气表 —— 那个场站根本没有燃气。

**电能默认选中**：现场 90% 是电表，不让你每次都先点一次。

**只有五个用能品种**：电 / 水 / 燃气 / 蒸汽 / 热力。
环境系统、冷热、压缩空气**不是**用能品种（场站不会「消耗环境」），
它们属于「环境设备」这个一级类型。

#### 层级怎么用

```
1号厂房-进线总表     level=1   ← 全厂总用电
  ├── 车间动力表      level=2   ← 车间用电
  │     ├── 1号机组   level=3   ← 单台设备用电
  │     └── 2号机组   level=3
  └── 照明回路表      level=2
```

上层 = 下层之和。如果对不上，差额就是「未计量部分」，这本身也是一个重要信息（说明有回路没装表）。

### 5. 能源品种

**这里说的「用能品种」专指会被计量、会被计费的那些能源**，标准有 5 种：

| 品种 | 编码 | 单位 | 对应的设备一级类型 |
| --- | --- | --- | --- |
| 电能 | `elec` | kWh | 电能表 / 逆变器 / 智能空开 / 发电机组 |
| 水 | `water` | m³ | 水表 |
| 燃气 | `gas` | m³ | 燃气表 |
| 蒸汽 | `steam` | t | 蒸汽表 |
| 热力 | `heat` | GJ | 热力表 |

> **环境系统 / 冷热 / 压缩空气不在用能品种里**（2026-11-01 定案）。
> 它们不是「烧的能源」——场站不会消耗环境。它们属于「环境设备」这个
> 一级设备类型。所以「场站声明用哪些能源」的下拉只有上表 5 项。

**品种由租户统一维护，不是写死的**。租户管理员在「运营配置 › 品种指标」里可以：

- **新增品种**（如氧气、氮气）—— 点右上「新增品种」，
  填编码（如 `oxygen`，业务主键、建好之后不能改）、名称、单位；
  新建的品种**默认算用能品种**，会自动进「场站声明能源品种」的下拉
- **配标准 key** —— 这个品种有哪些指标参数（见下方「能源参数」）
- 调整单位、数据形态（累积表底 / 瞬时读数）、支持的费率类型、图标、排序

> **二级设备类型不在这里配**。它有自己的入口：
> 「运营配置 → 设备类型」。原因见上一节的「六个核心字典」。

**改完立刻生效**：保存时会自动重建「能源品种」下拉的字典，
不需要重启服务，也不用等初始化。

> 新建品种**不会**自动生成对应的一级设备类型。要建档这类设备，
> 得先到「运营配置 → 设备类型」新增一个一级类型（编码、名称、**所属品种**、角色），
> 否则设备建档时选不到它。

> 只有**租户管理员**能维护品种（品种库是租户级主数据）。
> 客户账号看不到这个入口 —— 一个客户的品种改了会影响同租户下所有客户。

**品种决定三件事**：

1. **场站的可见品种**：场站建档时勾了哪几个品种，报表里就只出现哪几个
2. **设备建档的品种归属**：一级设备类型的下拉来自「设备类型」字典（不是品种清单），
   选中一级类型时**用能品种自动带出**
3. **设备分组的可纳入类型**：分组按品种收窄，避免把空调设备算进电能分项

**品种 ≠ 设备档案**。品种回答「这是哪种能源」，档案回答「这台表是谁家哪个型号」。
一个「电能表」档案下可以有普通表、关口表、逆变器三种设备；反过来，
一个品种下也有多个档案。两者不要混着配。

#### 型号绑定：厂家 key → 平台标准 key（配一次，同型号全用）

现场表计上报的字段名五花八门 —— 正泰叫 `Ep`，安科瑞叫 `U`，有的固件叫 `TotalEnergy`。
平台统计只认标准 key（`energy_reading`、`voltage_a`…），所以中间必须有一层映射。

**这一层配在「厂商与型号 › 技术档案」上，不是每台设备配一遍**：

```
厂商：正泰
  └ 型号：DDSU666
      技术档案：  Ep → energy_reading
                  U  → voltage_a
                  I  → current_a
                  ...            ← 同型号的 200 台设备共用这一份
```

改成三层，各管各的：

| 层 | 回答什么 | 配在哪 | 谁维护 |
| --- | --- | --- | --- |
| 二级设备类型 | 这台设备**该有**哪些标准 key | 品种指标页 | 租户 |
| 厂商型号 | 厂家 key **怎么映射**到标准 key | 厂商与型号 › 技术档案 | 租户 / 客户 |
| 设备 | 这台机的**例外** | 设备建档 › 测点管理 › 改为自定义 | 客户 |

**客户可以自建厂商和型号**：自己建的型号只有自己能改，改不了租户统一维护的
（那些是所有客户共用的，一个人改会连累其他客户的同型号设备）。

**接线方式会决定映射哪些相别**：型号的「接线方式」不只是个标签 ——

- **单相两线（1P2W）**：只有 A 相，`voltage_b` / `current_b` 这些点上不了
- **三相四线（3P4W）**、**三相三线（3P3W）**：A / B / C 三相都要

所以改接线方式时会**自动按相别补齐映射行**：你已经配了 `voltage_a`，
切成三相后会自动补出 `voltage_b`、`voltage_c` 两行（厂家键名留空，等你填）。
一条都没配时不会凭空塞一堆空行，而是给一个「按接线方式带出常用测点」的按钮。

切回单相**不会自动删**已有的 B/C 行 —— 你可能已经把厂家键名填进去了。
下方会提示「有 N 行是 B/C 相，单相表用不上」，删不删由你决定。

**建档时会告诉你缺什么**：选完型号后，如果它的技术档案没覆盖二级类型要求的
标准字段，测点管理上方会给出提示：

- 型号一条映射都没配 → 「该型号还没有配置技术档案 —— 需要 N 个标准字段，当前一个都没映射」
- 配了大半只漏几个 → 「还缺 N 个标准字段」+ 可展开查看具体是哪些

这两种情况的处理动作完全不同（一个要建档案、一个只要补一两项），所以分开说。
漏一个 key 的后果是数据照常进来、报表却少一列，而且系统不会报错。

> **新增品种不会立刻出现在所有页面**：查询设置的品种下拉按**场站声明的品种**
> 过滤（见[核心概念](/user/concepts) 铁律），新品种要到场站建档里勾上才生效。
> 这是刻意的 —— 没挂表的品种出现在报表里只会是一片空。

### 6. 能源参数

**遥测键名** —— 设备上报的每个数据点叫什么。

比如电表上报 `voltage_a = 228.3`，意思是「A 相电压 228.3 V」。

系统认的是**标准键名**，不是厂家自己的名字：

| 厂家可能叫 | 系统标准键名 |
| --- | --- |
| `Ua`、`A相电压`、`voltageA` | `voltage_a` |
| `Ep`、`正向有功`、`totalEnergy` | `energy_reading` |
| `P`、`总功率` | `power_total` |

**键名对不上，数据就进不来**。完整清单见[换成自己的数据](/user/onboarding)。

## 三、数据是怎么进来的（采集链路）

这一节讲的是「表上的数字，怎么变成报表里的电量」。搞不清这条链路，
现场最典型的症状是：**设备显示"已上报"，但电压/电流曲线全空，也不报错**。

### 三步走

```
① 设备/网关上报        厂家自己的代号  {"U":228.5,"I":10.2,"Ep":12345.6}
        ↓
② 键名翻译（规则链）    查这台设备的测点表 → 换成平台标准名
        ↓
③ 入库                  voltage_a=228.5  current_a=10.2  energy_reading=12345.6
```

第 ② 步叫「电表Key标准化」（节点名是历史原因，**对所有设备生效**，不只电表）。

### 翻译只认一件事：这台设备自己的「测点管理」

**运行期只看设备上存的那张表。** 不看型号、不看内置表。

```
设备「测点管理」里写的     →   就是最终生效的
没写的                     →   原样保留（不猜、不丢）
```

### 那张表从哪来：建档时自动填好

建档时点完型号，系统会算出一份：

```
① 内置表打底      常见厂家的默认代号（U→voltage_a、Ua→voltage_a…）
② 型号映射覆盖    你在「厂商与型号 → 技术档案」里配的，优先
```

然后在「测点管理」里显示出来，你可以逐行改。**点保存后，这份清单就存到设备上了。**

> **为什么不每次运行都去查型号？**
>
> 因为那样会出现两个说不清的情况：
> ① 你在设备里看到 3 行，实际生效 12 行，界面上看不出来；
> ② 别人改一次型号映射，你这台装好半年的表第二天数据就变错了，还查不到原因。
>
> 改成「保存时算一次、存下来」之后，**设备上看到的就是全部**，
> 改型号不会影响已经建好档的设备。

### 改了型号映射，已建档的设备怎么办

到「**厂商与型号 → 技术档案**」，打开那个型号，点
「**刷新该型号下所有设备**」。

⚠️ 这一步是**强覆盖**：会把该型号下所有设备的测点表按新映射重算，
**你在个别设备上手工改过的那几行会丢，而且不可撤销**。

所以不需要跟随新映射的设备，先在设备页把它们改成别的型号再刷新。

### 内置表能翻哪些、不能翻哪些

| 类别 | 会不会自动翻译 | 说明 |
| --- | --- | --- |
| 单相电压/电流/功率/功率因数/频率/正反向电度 | ✅ 会 | `U` `I` `P` `PF` `Freq` `Ep` 等 |
| 三相各相电压/电流/功率/功率因数 | ✅ 会 | `Ua` `Ub` `Uc` `Ia` … `PFc` |
| 反向电度、需量、谐波 | ❌ **不会** | 各厂家代号完全不同，必须到型号里自己配 |

> 为什么不全帮客户翻好：这几类每家的写法都不一样（`Ep-`/`Epr`/`Eq`/`MD`/`THDU`…），
> 猜错了**不会报错**，只会让报表里某个字段永远是空的、还查不出原因。
> 宁可少翻译，也不误翻译。

**没被翻译的键不会丢**，会以原始名字存着（比如 `Ep-`），可以在设备详情的
「最新遥测」里看到 —— 看到了就到型号里补一行映射即可。

### 两个现场常见故障

**① 设备显示已上报，但所有指标都是空的**

先看「最新遥测」里的键名：

- 键名就是 `voltage_a` / `energy_reading` → 已经翻译好了，问题在下游（时间窗口、场站过滤）
- 键名是 `U` / `Ep` 这种原始代号 → 测点表里没有这一行，去设备「测点管理」补，
  或到型号里配好再点「刷新该型号下所有设备」

**② 出现了键名 `values`，值是 `{"U":228,...}` 一整串**

旧固件把整包数据当成一个字段上报了（没有时间戳）。系统有兜底会自动拆开再翻译，
但如果拆不出来（值不是合法 JSON），就原样存着。这种情况需要升级固件。

## 四、三条必须记住的铁律

### ① 只有实体能承载数据

能挂遥测的只有「设备」和「资产」。所以：

- 想看到数据 → 必须有设备
- 想做汇总 → 用场站/区域/分项这些资产自动聚合

不能给「组织」挂数据，组织只是分类。

### ② 所有分析 = 根 + 过滤

每一个分析页的本质都是：**选一个根（场站），按某个维度过滤（分项/区域），算出结果**。

理解了这句，18 个分析页就是同一件事的不同切面。

### ③ 分项必须双挂

新建一个分项（比如「动力分项」），必须同时挂两个地方：

```
场站 ──Contains──→ 动力分项 ──Contains──← 电能（品种）
```

只挂场站不挂品种 → 分项能耗页面查不到数。
只挂品种不挂场站 → 其他场站也能看到它，造成串数据。

> 用导入脚本建分项时会自动双挂，手工在界面上建要记得两处都挂。

## 五、常见误解

| 误解 | 实际 |
| --- | --- |
| 「场站就是组织」 | 不是。组织是管理归属，场站是物理地点 |
| 「区域和分项可以同时看」 | 可以分别看，不能叠加 —— 会重复计算 |
| 「设备挂到场站就够了」 | 还要设 `层级`，否则总分关系建不起来 |
| 「虚拟表能自动汇总」 | 虚拟表要配计算规则，否则它自己也是空表 |
| 「换个键名系统能自动识别」 | 不能。系统只认标准键名，需要网关侧做映射 |
| 「设备档案就是设备类型」 | 不是。档案是厂商型号那一层；设备类型是 type1/type2 两级（品种 → 具体设备），分组按它收窄 |
| 「能源品种只有电水气汽四种」 | 不是。标准有 8 种，租户还能自己加；平台按品种库渲染，不写死 |
