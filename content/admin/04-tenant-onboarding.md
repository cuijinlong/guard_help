# 开租户与开客户

> 新客户进来，平台方要做哪几步。这一页是标准操作流程，脚本可直接执行。

## 一、先理解权限模型

这是最容易踩坑的地方：

- **系统管理员（SYS_ADMIN）不能直接建客户。**
  `POST /api/customer` 的权限注解只允许 `TENANT_ADMIN` / `CUSTOMER_USER`，用系统管理员调用会返回 `403`。
- 所以开通流程不是「系统管理员一路建到底」，而是：
  1. 系统管理员开租户；
  2. 系统管理员给这个租户建一个**租户管理员**账号；
  3. 后续的客户、客户账号都由**租户管理员**创建。
- 这也正是真实 SaaS 的分权方式：平台方只负责开通和交付管理员账号，租户内部结构由租户自己维护。

## 二、一条命令完成开通

```bash
bash 02-onboard.sh \
  --base http://127.0.0.1:8090 \
  --admin admin@example.com --admin-pass 'ChangeMe123!' \
  --tenant "环宇能源集团" \
  --tenant-email tenant@example.com --tenant-pass 'Tenant@12345' \
  --customer "星河工业园" \
  --customer-email customer@example.com --customer-pass 'Customer@123'
```

参数说明：

- `--tenant` + `--tenant-email/--tenant-pass`：开租户并交付租户管理员。以 SYS_ADMIN 调用时这三项必填。
- `--customer` + `--customer-email/--customer-pass`：建客户并交付客户账号。
- 只传 `--tenant` 就只开租户；直接用租户管理员调用时，可以只传 `--customer`。
- `--verify-only`：不创建任何东西，只跑最后一段验证。

**期望输出**：

```
✓ 租户已创建
✓ 租户管理员已创建（待激活）
✓ 租户管理员已激活并取得会话
✓ 客户已创建
✓ 客户管理员已创建并激活（可用该邮箱登录）
✓ 能源参数字典：1 个
✓ 四个维度根齐全
✓ 系统部件：726 个
✓ 能耗管理部件：32 个
✓ 全部验证通过
```

脚本是**幂等**的：重复执行只会提示「已存在，跳过/复用」，不会建出重复租户。

## 三、创建之后自动发生了什么

这些都是服务端钩子触发的，不是脚本做的：

| 触发点 | 自动创建 | 缺了会怎样 |
| --- | --- | --- |
| 建租户 | 能源参数字典（4 个品种：电/水/燃气/蒸汽）+ 计量器具档案（电能表/水表/燃气表/蒸汽表）+ 默认规则链 + 默认仪表板 | 查询设置的品种下拉为空；手工填报建不了类目；分项统计找不到单位 |
| 建客户 | 4 个维度根（用电分项/用能区域/用能性质/空间位置）+ 一套 `demo=true` 的演示数据（场站、类目、3 台表计、近 7 天遥测、拓扑） | 「用能结构」页对新建客户不可用；客户首次登录看不到任何数据 |

自动初始化失败**不会回滚主实体**，只记日志。所以开通脚本最后一定要跑验证段 —— 少一样就报错，不给「创建成功但页面空着」的假成功。

## 四、账号为什么必须「激活」

`POST /api/user` 创建出来的用户是 `enabled=false`，而且**请求体里的 password 字段会被忽略** —— 服务端只生成一个一次性激活 token。这是 ThingsBoard 的既有安全设计。

所以脚本创建用户后必须再走一步：

1. `GET /api/user/{userId}/activationLink` 拿到带 `activateToken` 的链接；
2. `POST /api/noauth/activate` 提交 `{activateToken, password}`，同时设置密码并启用账号。

跳过这一步，账号永远登不上。`02-onboard.sh` 已经内置这个流程。

## 五、验证隔离

```bash
bash 03-verify.sh \
  --base http://127.0.0.1:8090 \
  --tenant tenant@example.com --tenant-pass 'Tenant@12345' \
  --customer customer@example.com --customer-pass 'Customer@123'
```

必看的三项：

- `可读自己名下资产`、`可读自己名下设备`：数量和开通脚本报的一致；
- `客户访问租户端点被拒（HTTP 403）`：客户访问 `/api/tenant/devices` 必须 403；
- `客户删除版本被拒（HTTP 403）`：客户不能删盘查报告版本。

客户侧 403 有两种不同含义，别混：

- **访问租户端点 403** = 正确，说明隔离生效；
- **访问自己名下资产也 403** = 故障，通常是客户账号没进 `Customer Users` 用户组（见[故障排查](/admin/troubleshoot)）。

## 六、给客户看什么

新客户登录后默认能看到：

- 6 个租户级仪表板（能耗总览、实时能耗、分项能耗、区域能耗、历史能耗、基础报表）
- 3 台演示表计和近 7 天逐小时数据
- 4 个维度根构成的用能结构

这些演示数据都带 `additionalInfo.demo=true`，客户可以在界面上「清理演示数据」后换成自己的场站与设备。清理逻辑只删带标记的实体，不碰客户自建数据。

## 七、实测记录（2026-10-20，全新库）

| 项目 | 结果 |
| --- | --- |
| 开租户 | 成功，参数字典 1 个、品种 4 个 |
| 租户管理员 | 创建 → 激活 → 取得会话，全程无邮件 |
| 开客户 | 成功，维度根 4/4，演示设备 3 台 |
| 客户管理员 | 创建 → 激活 → 可登录 |
| 客户读自己资产 | 7 个（4 维度根 + 场站 + 类目 + 字典可见项） |
| 客户读自己设备 | 3 台 |
| 幂等性 | 重复执行全部提示「已存在」，无重复数据 |
