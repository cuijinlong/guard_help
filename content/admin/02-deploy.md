# 部署：先选场景

> 三条路，选一条走。每条都写清楚**在哪台机器、cd 到哪个目录**。

## 一、我是哪种情况？

| 你的情况 | 走哪条 | 需要 scp/ssh 吗 |
| --- | --- | --- |
| 就在当前电脑上试用，Docker 装好了 | [方案 A：本机 Docker](/admin/deploy-local) | 不需要 |
| 代码在这台电脑，要跑到另一台 Linux 服务器 | [方案 B：上传到服务器](/admin/deploy-remote) | 需要 |
| 服务器不能装 Docker，或要直接调 JVM | [方案 C：裸机部署](/admin/baremetal) | 视情况 |

不确定就先看下面两行：

- **你只有一台电脑**，想看到系统跑起来 → 方案 A。
- **你有一台云服务器**（阿里云/腾讯云/AWS…），想让它 7×24 挂着对外访问 → 方案 B。

## 二、三条路的共同点

不管走哪条，服务端流程是同一个顺序，只是执行位置不同：

```
准备文件  →  建库 + install  →  启动 + 建管理员  →  开租户与客户  →  验收 17 项
```

- **install 只建表和系统资源，不创建任何用户**
- **第一个管理员只能由 setup 接口创建**，且只在库里没有管理员时接受请求
- **验收脚本必须 17 项全通过**才算完成

所以顺序不能跳，也不能把「建管理员」提前到 install 之前。

## 三、命令里会出现的两种「在哪执行」标记

文档里每条命令前都有这样的标注：

```
【你的电脑 · 仓库根目录】
【服务器 · /opt/energy-app】
```

含义：

- **你的电脑**：写代码、有仓库、有 jar 的那台
- **服务器**：要 7×24 跑服务的那台
- 冒号后面是**必须先 cd 进去的目录**

下文所有命令都遵守这个约定。看到标注就要先确认自己在对应位置，`pwd` 可以随时核对当前目录。

## 四、装完之后的页面

- 本机：`http://localhost:8090/`
- 服务器：`http://服务器IP:8090/`

管理员账号是第 2 步里你设的邮箱密码。开租户后，客户用第 3 步里的客户邮箱登录。

## 五、卸载

三条路都可以彻底卸载，见[卸载与重置](/admin/uninstall)。Docker 方案的自检会列出容器、卷、网络、端口、目录五项，全空才算干净。
