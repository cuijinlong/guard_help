# 新客户上线：按流程做

> 客户只需填 **3 张表**，agent 一条命令建完全部数据，现场配好 RTU 就能采集。
> 全程不需要在界面上一个个点。

## 一、谁做什么

| 阶段 | 谁 | 做什么 | 耗时 |
| --- | --- | --- | --- |
| 1 | 平台方 | 开租户、交付租户管理员账号 | 1 分钟 |
| 2 | 租户管理员 | 建客户、交付客户账号 | 1 分钟 |
| 3 | **客户** | **填 3 张表**（Excel / CSV） | 15–30 分钟 |
| 4 | agent | 一条命令导入 | 1 分钟 |
| 5 | 客户现场 | 按清单配 RTU 网关 | 10 分钟 |
| 6 | 平台方 | 验收 | 1 分钟 |

第 1、2 步见[开租户与开客户](/admin/tenant)。本页讲第 3–6 步。

## 二、第 3 步：客户填表（唯一需要人工的环节）

### 2.1 下载模板

三个文件，用 **Excel 直接打开**即可编辑：

| 文件 | 内容 | 一行代表 |
| --- | --- | --- |
| [场站.csv](/downloads/templates/场站.csv) | 场站与分组 | 一个场站 |
| [设备.csv](/downloads/templates/设备.csv) | 设备清单 | 一台设备 |
| [点位.csv](/downloads/templates/点位.csv) | RTU 采集点 | 一个采集点 |

模板里带了示例行，**填完后把示例行删掉**。

> Excel 打开 CSV 时中文可能乱码：用「数据 → 从文本/CSV」导入，编码选 **UTF-8**。
> 或者直接用文本编辑器（VS Code、Sublime）填，更不会有编码问题。

### 2.2 表一：场站.csv

```csv
客户名称,场站名称,场站分组,用能区域,空间位置,用能性质,备注
星河工业园,1号厂房,A区,生产区,厂区北侧,生产用能,
星河工业园,2号厂房,,生产区,厂区南侧,生产用能,
```

| 列 | 必填 | 说明 |
| --- | --- | --- |
| 客户名称 | ✅ | 全部行填同一个客户名 |
| 场站名称 | ✅ | 同一客户内唯一。**按配电室/楼栋/车间划分**，不要按设备类型 |
| 场站分组 | ❌ | 填了会自动建「场站分组」资产并作为父级 |
| 用能区域 | ❌ | 如「生产区」「办公区」，会自动建维度资产并挂到本场站 |
| 空间位置 | ❌ | 如「厂区北侧」「3楼」，同上 |
| 用能性质 | ❌ | 如「生产用能」「非生产用能」，同上 |

**三个维度列的作用**：填了之后，「区域能耗」「空间位置」等分析页面才有数据。全留空不影响主流程，只是这几个页面为空。

### 2.3 表二：设备.csv

```csv
设备名称,所属场站,设备档案,层级,厂商,型号,分项,用能区域,空间位置,用能性质,备注
1号厂房-进线总表,1号厂房,电能表,1,威胜,DTSD341,动力分项,生产区,厂区北侧,生产用能,
1号厂房-照明回路,1号厂房,单相电能表,3,威胜,DDZY102,照明分项,生产区,厂区北侧,生产用能,
2号厂房-空压站表,2号厂房,电能表,2,安科瑞,ACREL DTSD1352,动力分项,生产区,厂区南侧,生产用能,
2号厂房-温湿度,2号厂房,温湿度变送器,3,,,,生产区,厂区南侧,生产用能,
```

| 列 | 必填 | 说明 |
| --- | --- | --- |
| 设备名称 | ✅ | 租户内唯一。**建议带场站前缀**，如 `1号厂房-进线总表` |
| 所属场站 | ✅ | 必须是【场站】表里出现过的名称 |
| 设备档案 | ✅ | 见下表 |
| 层级 | ✅ | `1` 总表（进线）/ `2` 分表（楼层、车间）/ `3` 支路表（末端回路） |
| 厂商 | ❌ | 必须是平台「厂商与型号」里已有的名称 |
| 型号 | ❌ | 必须归属于所选厂商 |
| 分项 | ❌ | 如「动力分项」「照明分项」。填了会自动建分项并双挂 |
| 用能区域/空间位置/用能性质 | ❌ | 留空则继承所属场站的维度 |

**设备档案可选值**：

| 档案 | 用于 | 能源品种 |
| --- | --- | --- |
| `电能表` | 三相四线（车间动力、进线） | 电能 |
| `单相电能表` | 单相两线（照明、插座） | 电能 |
| `水表` | 水表 | 水表 |
| `燃气表` | 燃气表 | 燃气 |
| `蒸汽表` | 蒸汽表 | 蒸汽 |
| `温湿度变送器` | 温湿度（非计量） | — |
| `网关` | RTU / 边缘网关本体 | — |

**层级的实际作用**：平台按 `层级` 做总分关系。总表 = 1，其下分表 = 2，末端 = 3。同一层级的多台表并列，自动聚合到上一级。

### 2.4 表三：点位.csv

```csv
设备名称,标准键名,点位地址,倍率,单位,备注
1号厂房-进线总表,energy_reading,40001,0.01,kWh,正向有功总电度
1号厂房-进线总表,voltage_a,40010,0.1,V,A相电压
1号厂房-进线总表,current_a,40016,0.001,A,A相电流
1号厂房-进线总表,power_total,40028,0.001,kW,总有功功率
```

| 列 | 必填 | 说明 |
| --- | --- | --- |
| 设备名称 | ✅ | 必须是【设备】表里的名称 |
| 标准键名 | ✅ | 平台认可的键名，见下方清单 |
| 点位地址 | ✅ | RTU 侧地址（Modbus 寄存器 / PLC 变量名） |
| 倍率 | ❌ | 默认 1。**填错会导致数值差 10 倍或 100 倍** |
| 单位 | ❌ | 仅备注用，平台按标准键名取单位 |
| 备注 | ❌ | 给人看的 |

#### 电能标准键名

| 键名 | 含义 | 单位 |
| --- | --- | --- |
| `energy` | 用电量（本周期增量） | kWh |
| `energy_reading` | 正向有功总电度（表底） | kWh |
| `energy_tip` / `energy_peak` / `energy_flat` / `energy_valley` | 尖/峰/平/谷电度 | kWh |
| `voltage_a` / `voltage_b` / `voltage_c` | 相电压 | V |
| `current_a` / `current_b` / `current_c` | 相电流 | A |
| `power_a` / `power_b` / `power_c` / `power_total` | 有功功率 | kW |
| `reactive_power_total` | 总无功功率 | kVar |
| `apparent_power_total` | 总视在功率 | kVA |
| `power_factor_total` | 总功率因数 | — |
| `frequency` | 频率 | Hz |
| `demand_max` | 最大需量 | kW |
| `load_rate` | 负载率 | % |
| `voltage_unbalance` | 电压不平衡率 | % |

#### 温湿度 / 水气汽

| 键名 | 含义 | 单位 |
| --- | --- | --- |
| `temperature` | 温度 | ℃ |
| `humidity` | 相对湿度 | % |
| `energy` | 用量 | m³ 或 t |
| `energy_reading` | 表底 | m³ 或 t |
| `power` | 瞬时流量 | m³/h 或 t/h |

> 完整 46 项见[概念与数据模型](/user/concepts)。

**单相表只填 A 相**。填 B/C 相会被脚本警告并跳过 —— 单相表本来就没有这两相，写 0 会让「相电压」报表把 0 当成真实读数。

**`energy` 和 `energy_reading` 不要同时填在同一台设备上**，否则会重复计量。二选一：
- 表计能出表底 → 填 `energy_reading`，平台自动做差
- 表计只出增量 → 填 `energy`

## 三、第 4 步：agent 导入

### 3.1 把三张表交给 agent

Excel 方式（需 `openpyxl`）：

```bash
# 三个 CSV 可以在 Excel 里合并成一个 xlsx：每个 CSV 一个工作表，表名分别为
# 场站 / 设备 / 点位
python3 scripts/05-import-customer-data.py 客户数据.xlsx \
  --base http://127.0.0.1:8090 \
  --tenant-admin tenant@example.com --tenant-pass 'Tenant@12345'
```

CSV 方式（零依赖，**推荐**）：

```bash
# 三个 CSV 放在同一目录，文件名必须是 场站.csv / 设备.csv / 点位.csv
python3 scripts/05-import-customer-data.py ./客户数据/ \
  --base http://127.0.0.1:8090 \
  --tenant-admin tenant@example.com --tenant-pass 'Tenant@12345'
```

### 3.2 先校验，不写库

```bash
python3 scripts/05-import-customer-data.py ./客户数据/ \
  --base http://127.0.0.1:8090 \
  --tenant-admin tenant@example.com --tenant-pass 'Tenant@12345' \
  --dry-run
```

**你会看到**：

```
读取 CSV 目录 客户数据
  场站 2 个 / 设备 4 台 / 点位 13 条
  ! 1号厂房-进线总表：同时上报了 energy_reading 和 energy，注意不要重复计量
  客户：星河工业园

✓ 校验通过（--dry-run，未写入）
```

有错会逐条列出**行号 + 原因**，改完再跑。

### 3.3 正式导入

去掉 `--dry-run` 重跑：

```
读取 CSV 目录 客户数据
  场站 2 个 / 设备 4 台 / 点位 13 条
  客户：星河工业园

创建场站、分组与维度...
  ✓ 分组「A区」
  ✓ 场站「1号厂房」（分组 A区）
  ✓ 用能区域「生产区」
  ✓ 空间位置「厂区北侧」
  ✓ 场站「2号厂房」...

创建分项...
  ✓ 分项「动力分项」（已挂场站 + 电能品种）
  ✓ 分项「照明分项」（已挂场站 + 电能品种）

创建设备...
  ✓ 1号厂房-进线总表        电能表      level=1
  ✓ 1号厂房-照明回路        单相电能表  level=3
  ✓ 2号厂房-空压站表        电能表      level=2
  ✓ 2号厂房-温湿度          温湿度变送器 level=3

设备接入信息（复制给现场配网关）：
  1号厂房-进线总表    a1b2c3d4e5f6...
  1号厂房-照明回路    b2c3d4e5f6a1...
  2号厂房-空压站表    c3d4e5f6a1b2...
  2号厂房-温湿度      d4e5f6a1b2c3...
```

## 四、第 5 步：现场配 RTU

把生成的 `rtu-config.csv` 交给现场电工或集成商。它长这样：

```csv
场站,设备,设备档案,层级,标准键名,点位地址,倍率,单位,accessToken
1号厂房,1号厂房-进线总表,电能表,1,energy_reading,40001,0.01,kWh,a1b2c3d4...
1号厂房,1号厂房-进线总表,电能表,1,voltage_a,40010,0.1,V,a1b2c3d4...
```

### 4.1 网关连平台

走**网关插件**（推荐，平台主动连网关）：

| 配置项 | 值 |
| --- | --- |
| 平台地址 | `http://平台域名或IP:8090` |
| 网关 accessToken | 见「设备」页选中网关设备 → 凭据 |

走 **MQTT 直连**：

| 配置项 | 值 |
| --- | --- |
| 服务器 | 平台域名或 IP |
| 端口 | `1883` |
| 用户名 | 设备的 `accessToken` |
| 密码 | 留空 |
| ClientID | 任意唯一值 |

> MQTT 默认关闭。要用需在 `.env` 设 `MQTT_ENABLED=true` 并映射 1883 端口，
> 重启后生效。

### 4.2 上报主题与格式

```
v1/devices/me/telemetry
```

```json
{"energy_reading": 12345.6, "voltage_a": 228.3, "current_a": 15.2}
```

### 4.3 逐条配点位

按 `rtu-config.csv` 的「点位地址 → 标准键名」配置，**倍率必须照抄**。

### 4.4 建议采集周期

| 数据 | 周期 |
| --- | --- |
| 电度（`energy_reading`） | 15 分钟 |
| 电压/电流/功率 | 1 分钟 |
| 温度/湿度 | 5 分钟 |

### 4.5 现场验证

在平台「设备」页选中设备 → 「最新遥测」，能看到数据即成功。

## 六、AI 预测需要多久数据

| 历史长度 | 效果 |
| --- | --- |
| < 7 天 | 只能拟合日周期，预测线趋于平直，页面提示数据不足 |
| 14 天 | 日 + 周周期都能估出，预测可用 |
| 30 天以上 | 能识别节假日效应 |

**所以刚接完网关的两周内 AI 页面是空的，这是正常的。** 演示环境已预置 14 天数据。

## 七、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 打开 CSV 中文乱码 | Excel 按 GBK 解析 | 用「数据 → 从文本/CSV」导入，编码选 UTF-8 |
| 点位地址变成 `4.0001E+04` | Excel 把数字当数值 | 该列设为「文本」格式，或用文本编辑器填 |
| 点位地址丢了前导零 | 同上 | 同上 |
| `所属场站「xxx」不在【场站】表里` | 名称不一致（多了空格/错字） | 逐字复制场站名 |
| `设备档案「xxx」无效` | 档案名写错 | 用第 2.3 节表格里的准确名称 |
| `标准键名「Ua」不识别` | 用了厂家自己的键名 | 必须换成平台标准键名 |
| 导入成功但页面空 | 数据还没上报 | 先确认「最新遥测」有数据 |
| 数值差 10 倍 | 倍率填错 | 按表计说明书核对倍率 |
| 分项能耗没数 | 分项没双挂 | 重新导入（脚本会自动补关系） |
| AI 页面无数据 | 历史不足 14 天 | 等待数据积累 |
